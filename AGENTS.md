# AGENTS.md

This file provides guidance to agents when working with code in this repository.

## Project
This is an **openFrameworks addon** (`ofxOceanodeLaser`) that registers laser/ILDA node models into the `ofxOceanode` visual programming framework, wrapping `ofxLaser`. There is no build system inside this repo — projects are generated by the openFrameworks Project Generator using [`addon_config.mk`](addon_config.mk:1). Build/run/test the [`example/`](example/) project through OF (Xcode / Make / VS), not from this addon directory.

## Hard dependencies (from [`addon_config.mk`](addon_config.mk:27))
`ofxOceanode`, `ofxImGui`, `ofxLaser`, `ofxOceanodeVectorGraphics`, `ofxOceanodeOsc`. The example also needs `ofxFatLines`, `ofxOsc`, `ofxPoco`, `ofxOpenCv`, `ofxNetwork`, `ofxSvg`, `ofxXmlSettings`, `ofxImGuiSimple` (see [`example/addons.make`](example/addons.make:1)).

## Critical build defines / excludes
- `ADDON_DEFINES = OFXLASER_DISABLE_GUI` is mandatory — `ofxLaser`'s own ImGui UI must stay off; this addon draws its own UI inside Oceanode's ImGui context via [`ildaController::draw()`](src/ildaController.h:61).
- `ADDON_SOURCES_EXCLUDE` strips `ofxLaser/libs/ofxImGui/*` and `ofxLaser/libs/imgui/*` to avoid duplicate ImGui symbols with `ofxImGui`. Do not remove these excludes.

## Registration entry point
Host apps integrate the addon via [`ofxOceanodeLaser::registerCollection(oceanode)`](src/ofxOceanodeLaser.h:83), which calls `addController<ildaController>()` and registers `ildaProjector`, `ildaShape`, `ildaMask`, `laserSimulator`, `polyOscSender`, `ildaDebugger` — all under the `"ILDA"` category. `polyOscSender` is registered with the OSC controller (`o.getController<ofxOceanodeOSCController>()`), not the ILDA controller.

## Non-obvious conventions
- **Hardcoded laser canvas is 800×800.** Zone created in [`ildaController()`](src/ildaController.h:19) is `(0,0,800,800)`; normalization throughout the codebase divides coords by `800.0f` (see [`ildaDebugger::update`](src/ofxOceanodeLaser.h:32), [`polyOscSender::update`](src/polyOscSender.cpp:97)). Don't change the magic 800 unless you update all sites.
- **Warp points persistence is custom, not via Oceanode presets.** [`ildaController`](src/ildaController.h:30) reads/writes `bin/data/warpPoints.json` directly with `ofLoadJson` / `ofSavePrettyJson`; this is independent of preset save/load.
- **`ildaShape` must guard against preset loads.** Overrides [`presetWillBeLoaded`](src/ildaShape.h:57) / [`presetHasLoaded`](src/ildaShape.h:61) to flip a `disable` flag — without this, fatline listeners fire mid-load and crash. Copy this pattern in any new node that holds `ofxFatLine` listeners.
- **Frozen-state passthrough.** When `controller->isFrozen()` is true, `ildaShape` re-draws its last `storedInput` instead of the new input — laser output never goes black on freeze.
- **OSC host parameter is marked `ofxOceanodeParameterFlags_DisableSavePreset`** in [`polyOscSender::setup`](src/polyOscSender.cpp:16); host is sourced from the OSC controller via `controller->addSender("Polylines")` and the `hostEvents["Polylines"]` listener — never serialize it.
- **`numInputs` in `polyOscSender` is an inspector parameter** loaded in [`loadBeforeConnections`](src/polyOscSender.h:25) so that the dynamically created `In N` parameters exist before patch connections are restored. Required pattern for any node with a variable input count.
- When `polyOscSender` has no data to send it emits a black diagonal as a buffer-clearing message — do not "optimize" the empty-message branch away.
- **Raw laser shapes are forwarded to the Laser Simulator.** For every shape that passes the black-threshold test, `ildaShape` calls [`controller->publishLaserShape(fat)`](src/ildaShape.h:54) before `drawDot`/`drawPoly`. `ildaController` accumulates a flat XYRGB + `-1` frame buffer (`latestSimulatorData`) that `laserSimulator` reads each frame. The buffer is cleared automatically when the first shape of a new frame is published, using `ofGetFrameNum()` as the frame stamp.

## Code style (observed, no linter)
- Headers use `#ifndef <name>_h` include guards (note: [`ildaController.h`](src/ildaController.h:8) still guards as `testController_h` — legacy, leave alone unless refactoring).
- Mixed tabs and spaces inside method bodies; match the surrounding file.
- `using namespace std;` is assumed (bare `vector`, `string`, `shared_ptr` everywhere).
- Node models: constructor only sets name + stores deps; all parameter wiring goes in `setup()`. Listeners stored in `ofEventListeners parameterListeners` / `listeners` and pushed with `.push(param.newListener(...))`.
